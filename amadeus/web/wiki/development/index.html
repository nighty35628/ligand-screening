目录结构#

amadeus/
  server.py          HTTP服务与固定案例推断
  workflow.py        项目、动作、Agent工具与导出
  data_engine.py     提取、审计、转换与结构特征
  engine.py          回归模型比较与搜索
  tabular.py         CSV入口与二分类
  provider.py        对话、Search、Fetch适配
  examples/          标准案例数据、映射与来源
  web/               工作台、案例快照与生成的Wiki
allis_delivery/      纳米晶双路模型
allis_benchmark/     统一基线与指标评价
results/             已完成运行的公开结果
scripts/             数据准备、核验和页面构建
docs/wiki/           Wiki源文章与样式
tests/               单元与工作流检查

接入新数据集#

  1. 将来源、许可、字段单位和样本身份写入数据说明。
  2. 准备历史表、候选表与mapping，先使用现有上传入口完成分析。
  3. 需要组成特征时参考现有准备脚本，不假定任意化学式都已被通用界面解析。
  4. 检查组隔离、候选标签、保存重开及导出。
  5. 需要成为内置案例时，再更新examples、research-cases元数据与快照构建脚本。

增加模型或Agent工具#

回归模型在engine.py的估计器创建和比较列表中注册，新增搜索参数应放入内层优化。保存统一的scores、candidates、order等字段，保证前端继续读取。

新增Agent工具需要在TOOLS定义参数，在函数分发映射中接到实现，并确认状态与导出。新增HTTP动作还需要在workflow.start中接入；工具schema不会自动创建HTTP路由。

必要测试#

.venv-allis/bin/python -m unittest discover -s tests -p test_data_engine.py
.venv-allis/bin/python -m unittest discover -s tests -p test_material_snapshots.py
node tests/test_demo_adapter.cjs
python3 scripts/check_wiki.py

快照测试检查冻结结果接线，不重新训练；数据引擎测试模拟提取响应，不消耗API。真正的模型重训与完整工作流命令在各案例页单独说明。

构建文档与在线部署#

python3 scripts/build_wiki.py
python3 scripts/check_wiki.py

Wiki由标准库Python构建，文章源在docs/wiki/content.py。生成独立HTML、搜索索引与站点地图，更新前端哈希清单。GitHub Actions在main分支相关路径变化后校验资产并发布Pages；在线站点只包含静态资源。

演示在网站根目录，文档位于/wiki/，研发证据页位于/evidence.html。工作台、证据页与Wiki互相链接。
